# 优化图片输入展示

日期：2026-11-10；状态：已实施

## 目标与范围

截图中的 `@/var/folders/.../pasted-image-....png` 当前作为普通文字占满输入框。参考 Codex CLI 的编号图片标签，将图片输入转换为真实 Host 附件，并在输入区域显示紧凑的 `[Image #1]`，使长路径不再遮挡草稿。

参考源码：<https://github.com/openai/codex/blob/main/codex-rs/tui/src/bottom_pane/chat_composer.rs>（图片路径识别、编号标签、附件与文字分别保存）。本插件复用 pi-tui 原生文字编辑器，将标签放在编辑框上方独立一行，避免改变原生文字光标、换行、撤销和补全坐标。

## 实施方案

- 识别粘贴的本地图片路径（绝对、相对、home、引号、shell 转义、`file://`），以及文字中的显式 `@` 图片引用。普通文字、非图片引用与 slash 命令保持原有语义。
- 使用既有附件服务和 8 MiB 限制保存图片；校验图片格式。加载成功后从待插入文字中移除路径，失败保留原始文字并显示错误。
- 图片加载期间按顺序暂存后续输入，完成后再交给原生编辑器，保证快速粘贴、继续输入、立即 Enter 的顺序。生命周期结束取消未处理输入；会话切换前等待输入处理完成。
- 所有图片入口（路径粘贴、`/attach <path>`、`/attach paste`）共享 pending attachments；编辑框上方展示编号标签与管理提示，窄终端截断。预览和移除复用 `/attachments`，空输入框 Backspace 可移除最后一张图片。
- 提交成功后清空标签，Host 拒收时保留；已有每会话附件草稿随会话切换保存、恢复。历史用户消息中的图片也展示为编号标签，不泄露长文件名。实际发送仍使用原始 Host 图片引用。

## 影响区域与约束

`src/ui/prompt-editor.ts`、图片输入辅助模块、`src/ui/app.ts`、用户消息投影及相关测试和 fake-TTY 探针。保留现有未提交修改；不新增运行时依赖；每个源码文件不超过 1000 行。

## 验证与验收

- 单元测试覆盖路径解析、混合文字、多图、失败保留、普通文字与命令隔离、标签宽度、鼠标坐标、顺序和提交拒收。
- 运行 `pnpm check`。
- 使用真实 Host、隔离临时 profile 和本地模型响应服务运行 fake-TTY 探针，覆盖主屏和全屏：长路径不可见、编号标签可见、原图实际进入请求、移除与清空生效、无行宽溢出。

## 实施与验证记录

- `pnpm check` 通过：103 个测试文件、1497 项测试，类型检查与构建通过；其中新增图片输入测试 29 项、用户图片历史投影测试 1 项。
- 新增 `runtime/image-input.ts` 识别并保存图片引用；`ui/image-input.ts` 复用附件状态和管理入口；`ui/paste-input.ts` 顺序处理图片读取期间的后续输入和快捷键。
- 编辑框附件行与 slash 菜单共同计算高度，鼠标坐标减去附件行偏移；普通文字粘贴仍同步交给原生编辑器，保留大段粘贴展开和撤销。
- 用户图片历史采用编号标签；工具和 assistant 图片输出继续沿用原有文本投影。
- 真实 Host 探针 `node scripts/fake-tty-image-input.mjs`：主屏与全屏均 PASS，各发送 1 张图片，PNG 字节与源文件完全一致；已移除、已清空的图片未进入请求；无行宽溢出。全屏通过 PageUp 回看历史验证用户消息标签。
- 探针使用本地 mock 模型服务验证请求内容，不代表外部视觉模型识别验收。沙箱内监听 `127.0.0.1` 报 `EPERM`，经授权在沙箱外运行成功。
