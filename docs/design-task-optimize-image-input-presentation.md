# 优化图片输入展示

日期：2026-11-10；状态：已实施

## 目标与范围

参考 Codex CLI 截图中的缩略图与编号图片标签，在同一输入面板展示图片预览和 `› [Image #1]` 文字输入。继续将本地图片路径转换为真实 Host 附件，使长路径不占用草稿。

本插件复用 pi-tui 原生文字编辑器。标签仅作为显示前缀，缩略图使用 pi-tui `Image`，附件与文字分别保存。

## 实施方案

- 识别粘贴的本地图片路径（绝对、相对、home、引号、shell 转义、`file://`），以及文字中的显式 `@` 图片引用。普通文字、非图片引用与 slash 命令保持原有语义。
- 使用既有附件服务和 8 MiB 限制保存图片；校验图片格式。加载成功后从待插入文字中移除路径，失败保留原始文字并显示错误。
- 图片加载期间按顺序暂存后续输入，完成后再交给原生编辑器，保证快速粘贴、继续输入、立即 Enter 的顺序。生命周期结束取消未处理输入；会话切换前等待输入处理完成。
- 所有图片入口（路径粘贴、`/attach <path>`、`/attach paste`）共享 pending attachments；标签与文字同行显示，最多占用约半行，窄终端使用独立标签行。预览和移除复用 `/attachments`，空输入框 Backspace 可移除最后一张图片。
- 输入面板缩略图由 `showImageThumbnails` 控制，默认关闭，可在 `/settings` 中即时切换。开启后顶部自动展示最多两张缩略图，单张最多 16 列、4 行，多图与短终端按总行数预算缩小。使用 Host 保存的附件字节和可取消的异步读取；只缓存当前展示图片，移除、切换草稿、退出时释放缓存并拒绝过期结果。
- 不支持图片协议、终端过窄或过矮、图片格式无法显示、预览读取失败时保留可发送的编号附件。沿用 pi-tui 的协议支持；插件适配层为 iTerm2 恢复全屏图片能力并负责最终绘制顺序。
- 补全菜单保持在整个输入面板上方；原生编辑器按扣除标签后的宽度处理文字，渲染和鼠标事件适配新增行列偏移，保留原生光标、换行、撤销和补全行为。
- 提交成功后清空标签，Host 拒收时保留；已有每会话附件草稿随会话切换保存、恢复。历史用户消息中的图片也展示为编号标签，不泄露长文件名。实际发送仍使用原始 Host 图片引用。

## 影响区域与约束

`src/ui/prompt-editor.ts`、图片输入与缩略预览辅助模块，以及相关测试和 fake-TTY 探针。复用现有 `app.ts` 附件草稿和用户消息投影；不新增运行时依赖；每个源码文件不超过 1000 行。

## 输入区图片查看（2026-11-13）

### 目标与范围

结合参考截图，在输入区展示更清晰的图片缩略图，并提供直接打开大图的操作。保留本任务此前的 `@` 消耗修复、附件提交与草稿语义。

### 实施方案

- 单图缩略图最大提高到 16 列、4 行；多图和短窗口按既有预览总行数预算缩小，最多自动读取两张图片。图片标签与文字继续同行展示。
- 输入区 `Alt+I` 打开图片查看器；支持鼠标事件的全屏模式可点击缩略图或编号标签打开对应图片。预览行提示快捷键；无图片协议时仍可通过快捷键查看附件信息。
- 查看器保留当前草稿，按 `←/→` 查看其他待发送图片，`Enter/Esc` 关闭并回到输入框。加载和读取失败在查看器内显示；关闭、换图、会话取消时终止旧读取，忽略迟到结果；已有弹窗打开时不重复打开。
- 图片导入期间排队的按键在处理时遵循当前焦点：若先打开查看器，随后排队的 Enter 关闭查看器，避免发送底层草稿。
- 共用图片查看器供 `/preview` 与 `/attach preview` 使用。图片尺寸随窗口宽高重新计算，协议行保留完整载荷，不进入普通文字截断或填充流程；不支持协议时显示文件信息和文字回退。
- 仅添加本地 UI 交互，不新增依赖。主屏保留原生滚动与鼠标行为，通过快捷键打开；每个源码文件保持少于 1000 行。

## iTerm2 全屏图片（2026-11-13）

### 目标与现状

当前实际环境为 iTerm2 且 `fullscreen: true`。pi-tui 1.4.0 的 `TuiAltScreen.beforeTerminalStart` 将图片能力改为 `null`，因此此前六种探针中的全屏 iTerm2 仅验证文字回退。本次要求保留全屏并真正输出图片。

### 实施方案

- 在插件的全屏类上增加 iTerm2 适配层，继续复用 pi-tui 的布局、滚动、鼠标、焦点和差分渲染，不访问其私有字段。原始检测为 iTerm2 时，在父类启动后恢复该能力；退出沿用父类的能力恢复。不强制开启未知终端、tmux 或显式禁用的图片能力。
- 每帧同步捕获父类终端输出，移出其中的 iTerm2 图片载荷及相对上移指令。文字和清除操作完成后，按最终屏幕行的绝对坐标绘制图片，再恢复编辑光标，所有输出仍放在同一个同步更新块内。
- 从 pi-tui 图片行的上移距离与列位置确定图片保留区域。越过视口边界的图片不输出，图片下方保留一行，避免协议隐式移动光标触发滚屏；宽高按字符格限制。参照 [iTerm2 图片协议](https://iterm2.com/documentation-images.html) 的 `width`、`height` 和 `preserveAspectRatio` 保持比例。
- 位置、尺寸、图片内容变化和移除沿用父类的整屏清除，消除旧图片；稳定图片区域内有文字变动时重新绘图。只改变区域外的状态或输入时不重新发送载荷，避免等待计时器反复上传原图。
- 只缓存当前视口中图片行的解析结果；位置或终端尺寸变化时重新解析，图片移除和退出时释放。稳定帧复用图片位置，避免每次刷新都扫描并重建大体积载荷。
- 保留上一阶段的缩略图缓存、弹窗时暂停背景缩略图、异步取消和附件发送语义。更新原先宣称全屏 iTerm2 文字回退的当前说明，历史验证记录保留当时的边界。

### 验证与验收

- 原生全屏渲染回归覆盖启动能力、退出恢复、图片输出顺序、光标恢复、稳定帧与输入更新无重复上传、多图移除与移动、重叠弹窗、窗口缩放、滚动裁剪，以及 Kitty/无协议隔离。
- 真实 Host 探针对全屏 iTerm2 必须观察到自动缩略图和大图协议，不能再把文字回退计为该场景通过；保留六组合的鼠标、切图、草稿和原图发送校验。
- 运行定向测试、`pnpm check` 与真实 Host 图片探针，区分终端协议验证与物理终端像素验收。

### 实施结果

- 新增 `ImageAltScreen`，通过保护的生命周期与公开屏幕快照适配 iTerm2；`TimedAltScreen` 继承该适配层，保留绘制时间统计。未改动 pi-tui 依赖文件和用户 profile。
- 启动能力回归在旧实现上按预期失败（全屏后 `images: null`）；新增的 12 项回归全部通过。图片、等待绘制与滚动相关 6 个文件共 96 项通过。
- 最终 `pnpm check` 通过：121 个测试文件、1773 项测试，类型检查与构建通过。
- 最终真实 Host 图片探针六种组合全部 PASS；其中 `fullscreen-iterm2` 观察到 10 个含图片的终端帧，自动单图/双图缩略图与大图均输出真实 PNG 载荷。实际终端输出通过了文字清除在前、图片使用绝对坐标在后、限定高度、恢复编辑光标的断言，不再按文字回退验收。各组合仍只发送 1 张原始字节一致的图片，无文字行宽溢出。
- 探针使用本地 mock 模型服务，经授权在沙箱外监听回环端口；物理 iTerm2 像素与外部视觉模型未自动验收。现有用户安装为打包副本，需要重新安装新构建并重启才能加载适配层。
