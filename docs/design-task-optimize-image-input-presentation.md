# 优化图片输入展示

日期：2026-11-10；状态：已实施

## 目标与范围

参考 Codex CLI 截图中的缩略图与编号图片标签，在同一输入面板展示图片预览和 `› [Image #1]` 文字输入。继续将本地图片路径转换为真实 Host 附件，使长路径不占用草稿。

本插件复用 pi-tui 原生文字编辑器。标签仅作为显示前缀，缩略图使用 pi-tui `Image`，附件与文字分别保存。

## 实施方案

- 识别粘贴的本地图片路径（绝对、相对、home、引号、shell 转义、`file://`），以及文字中的显式 `@` 图片引用。普通文字、非图片引用与 slash 命令保持原有语义。
- 使用既有附件服务和 8 MiB 限制保存图片；校验图片格式。加载成功后从待插入文字中移除路径，失败保留原始文字并显示错误。
- 图片加载期间按顺序暂存后续输入，完成后再交给原生编辑器，保证快速粘贴、继续输入、立即 Enter 的顺序。生命周期结束取消未处理输入；会话切换前等待输入处理完成。
- 所有图片入口（路径粘贴、`/attach <path>`、`/attach paste`）共享 pending attachments；标签与文字同行显示，最多占用约半行，窄终端使用独立标签行。预览和移除复用 `/attachments`，空输入框 Backspace 可移除最后一张图片。
- 输入面板顶部自动展示最多两张缩略图，单张最多 12 列、2 行，并根据终端高度减少展示数量。使用 Host 保存的附件字节和可取消的异步读取；只缓存当前展示图片，移除、切换草稿、退出时释放缓存并拒绝过期结果。
- 不支持图片协议、终端过窄或过矮、图片格式无法显示、预览读取失败时保留可发送的编号附件。沿用 pi-tui 的协议支持；全屏模式下 pi-tui 禁用 iTerm2 图片协议。
- 补全菜单保持在整个输入面板上方；原生编辑器按扣除标签后的宽度处理文字，渲染和鼠标事件适配新增行列偏移，保留原生光标、换行、撤销和补全行为。
- 提交成功后清空标签，Host 拒收时保留；已有每会话附件草稿随会话切换保存、恢复。历史用户消息中的图片也展示为编号标签，不泄露长文件名。实际发送仍使用原始 Host 图片引用。

## 影响区域与约束

`src/ui/prompt-editor.ts`、图片输入与缩略预览辅助模块，以及相关测试和 fake-TTY 探针。复用现有 `app.ts` 附件草稿和用户消息投影；不新增运行时依赖；每个源码文件不超过 1000 行。

## 验证与验收

- 单元测试覆盖路径解析、混合文字、多图、失败保留、普通文字与命令隔离、标签宽度、鼠标坐标、顺序和提交拒收；补充两种图片协议、预览缓存、异步取消、Unicode 换行与撤销、补全位置验证。测试显式设置并恢复终端能力，避免依赖运行测试的终端。
- 运行 `pnpm check`。
- 使用真实 Host、隔离临时 profile 和本地模型响应服务运行 fake-TTY 探针，覆盖主屏与全屏的无图片协议、Kitty、iTerm2 共六种组合：长路径不可见、标签同行、支持的组合输出尺寸受限的图片协议、移除与发送后清除缩略图、原图实际进入请求、文字无行宽溢出。图片协议行按协议尺寸验收。

## 缩略预览实施与验证记录（2026-11-10）

- `pnpm check` 通过：110 个测试文件、1605 项测试，类型检查与构建通过；新增预览回归 9 项、带标签的文字编辑回归 1 项，并更新原有展示断言。
- `node scripts/fake-tty-image-input.mjs` 六种组合全部 PASS：每种组合实际发送 1 张图片且原始 PNG 字节一致；已移除和已清空的图片未进入请求；文字无行宽溢出。
- 主屏 Kitty、全屏 Kitty、主屏 iTerm2 均观察到自动单图与双图缩略预览协议；移除和发送后预览清除。全屏 iTerm2 遵循 pi-tui 的文字回退。
- 探针只验证真实 Host 到本地 mock 模型的请求和终端协议输出，不代表外部视觉模型识别或物理终端像素显示验收。沙箱禁止监听回环端口，探针经授权在沙箱外运行。
