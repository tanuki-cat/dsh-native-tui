# 命令补全列表向上展示

## 目标与范围

参考提供的 Codex CLI 截图，将 `/` 命令及子命令候选展示在输入框上方。保持命令名与说明分列对齐，选中项使用 `›` 和蓝色整行高亮。保留已有输入框、状态栏、命令执行与补全契约。

## 现有实现

- `TuiAutocompleteProvider` 提供命令、技能、文件和会话候选，`PromptEditor` 继承 pi-tui 1.4.0 的 `Editor`。
- 原生编辑器处理异步取消、匹配、选择、插入、历史和光标；渲染结果依次是上边框、输入、下边框、候选列表。
- 依赖没有公开的候选位置配置，只有公开输入/鼠标接口及受保护的边框渲染钩子。

## 实施方案

1. `PromptEditor` 通过受保护的下边框钩子记录原生渲染边界，将 `/` 候选行移动到整个输入框之前；不访问依赖私有字段、不改 node_modules，不重新实现补全状态机。
2. 继续使用原生候选的命令/说明列布局，将选中前缀改为 `›`，通过独立的补全选中色实现全宽蓝底；plain 主题保留可辨识前缀且不加 ANSI。菜单左侧命令文字与输入文字对齐。
3. 请求候选时通过公开的 provider 接口和数量 setter 配置显示上限：命令最多八项，文件/会话保持原生五项；短终端和高度变化时按输入及 chrome 预留空间裁剪，保持当前选中项可见，并保留原生滚动提示。
4. 保存候选和输入行的新旧位置映射，鼠标点击、滚轮和输入定位仍转交原生编辑器。硬件光标标记随输入行一起移动。
5. 只调整 `/` 菜单，包括子命令与技能；`@file`、`@@session` 保留原生布局及插入行为。
6. 将输入框上方的菜单视为编辑器组件的一部分，两种终端布局均随菜单打开向上占用空间，输入框及底部状态维持在末端。
7. 全局 Esc 消费输入后会绕过原生编辑器的自动重绘；在清空草稿后显式请求重绘，保证候选与输入立即从屏幕移除，保留原有清空草稿语义。

## 影响区域

- `src/ui/prompt-editor.ts`、`src/ui/theme.ts`、`src/ui/app.ts`
- 输入框及补全回归测试、真实 Host fake-TTY 探针、README

## 约束

- 路径、命令值和候选替换前缀保持原样，显示用的 `›` 不进入草稿或提交。
- 宽度按终端显示列计算，中文、emoji、窄屏不越界；颜色不得延伸到输入框或状态栏。
- 候选取消、重新过滤、鼠标选择和异步结果更新后清理旧布局映射，避免误点或光标错位。
- 验证边框钩子与渲染行分界这一依赖适配点，升级 pi-tui 时可由回归测试发现变化。

## 验证与验收

- 先新增回归并确认旧实现失败：候选在输入上方、两列对齐、整行高亮、单个硬件光标、键盘选择和提交、短屏滚动、鼠标位置转换、取消及文件候选不受影响。
- 运行相关定向测试及 `pnpm check`。
- 使用独立临时 profile/工作区运行真实 Host 探针，覆盖普通/全屏模式下 `/`、命令过滤、子命令、Tab、Enter、Esc 和实际渲染顺序。无需真实模型 API。

## 验证结果（2026-11-09）

- 新增 18 项持久回归，覆盖菜单顺序、两列对齐、主题与全宽选中行、Unicode/窄屏、短屏裁剪、鼠标坐标、重新过滤、插入与提交、取消，以及文件候选布局和五项上限。首批用例在旧实现下复现 10 项失败。
- `pnpm check` 通过：typecheck、102 个测试文件 / 1464 项测试、build。
- `node scripts/fake-tty-slash-autocomplete.mjs` 四组通过：普通/全屏 × 100/50 列。真实 Host 确认候选在输入上方、蓝色选中、八项候选、底部位置稳定、↑/↓、Tab、Enter、子命令、Esc 及全屏鼠标选择均正常。
- 探针复现了全局 Esc 清空状态后未重绘的旧问题；补充重绘请求后，候选和输入立即从终端消失。
- 同时运行两个独立探针进程，各自四组均通过；临时目录、profile 与随机端口相互隔离。探针确认模型请求数为 0，未使用真实模型 API。
- 探针语法检查及 `git diff --check` 通过。Host 探针监听本机随机端口，需要沙箱外运行权限。
