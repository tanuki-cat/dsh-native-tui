# 修复工具完成后的审批回执换位

日期：2026-11-10；状态：已实施

## 目标与范围

工具调用先展示、审批弹窗关闭后追加回执；工具完成时两者应保持相对位置。当前工具块的 `seq` 从调用事件更新为结果事件，回执插入逻辑比较该序号，导致回执从工具下方移动到上方。原生调用和 PTC 子调用、父 `run_code` 均受影响。

## 实施方案

- 工具块新增仅用于展示排序的 `positionSeq`，记录首次创建该块的事件序号，后续结果、失败和停止只更新内容与状态，不改变展示位置。
- 原生 `tool/call`、PTC dispatch start 使用调用序号。缺少调用记录、仅保留结果的历史从首次结果建立位置，不虚构此前的位置。
- `seq` 继续指向当前结果事件，保留现有事件语义；Session 日志、callId/subCallId、审批协议、工具执行及 `/tool`、`/diff` 索引不变。
- renderer 插入本地回执时，工具块使用 `positionSeq ?? seq`；已有 assistant stream 锚点和其他块的排序逻辑保持不变。位置计算在多文件汇总前执行，回执继续作为聚合边界。
- 历史裁剪生成的无序号提示是装饰行，不消费回执锚点，避免保留窗口缩小时将回执提到工具前。

## 影响区域与约束

`src/ui/transcript.ts`、`src/ui/transcript-renderer.ts`，新增审批顺序回归并增强真实 Host 展示探针。沿用 `dsh-ci-test-reliability` 的异步验证约束：通过握手文件等待授权后、工具尚未完成的真实帧，不依靠固定延时采样。

## 验证与验收

- 先运行新增回归，确认旧实现发生换位；修复后验证原生/PTC × bash/edit × 允许/拒绝/取消，从调用、审批回执出现、决策记录、结果写入到历史重放的顺序一致。
- 断言结果 `seq` 仍正确、首次位置稳定、组件复用、并行调用和多个回执不会错位、无 start 的结果可回退。保留多文件汇总、历史裁剪与既有 stream notice 回归。
- 运行 `pnpm check`。
- 增强 `scripts/fake-tty-transcript-presentation.mjs`：允许执行时使用有截止时间的握手等待，捕获回执在 pending 工具之后，再允许工具完成；允许和拒绝场景均检查每个可比较帧的相对顺序。覆盖主屏/全屏与 PTC compact/detailed，继续验证实际落盘、审批结果、配色、展开及主屏历史。

## 实施与验证记录

- `pnpm test tests/approval-order.spec.ts --bail=1` 在修改实现前按预期失败：工具完成后，回执位于第 4 行、工具位于第 6 行，违反稳定顺序断言。
- 新增 19 项持久回归：12 组原生/PTC × bash/edit × 允许/拒绝/取消生命周期；2 组无 start 的结果回退；2 组部分停止；并行调用逆序完成、历史裁剪后重建、多文件汇总边界各 1 项。保留结果 `seq`、组件复用、原始诊断和实际 diff 断言。
- `pnpm check` 通过：112 个测试文件、1658 项测试，类型检查与构建通过。
- `node scripts/fake-tty-transcript-presentation.mjs` 六组全部 PASS：主屏/全屏 × 允许/拒绝四组，主屏 PTC compact、全屏 PTC detailed 两组；每组观察到 2–4 个同时包含工具与回执的真实帧，顺序均为工具在前、回执在后。
- 允许场景通过握手确认审批回执已经出现且工具尚未完成，再释放真实 shell；拒绝场景确认执行标记不存在。保留实际源码落盘、错误状态、圆点配色、展开和主屏无历史清除断言。

- 探针使用隔离临时 profile 与本地 mock provider，未调用真实外部模型；回环端口和 PTC 内层沙箱经授权在沙箱外运行。探针语法检查及 `git diff --check` 通过。
